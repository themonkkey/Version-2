# Swarna Andhra GVA Assistant — Status

_Snapshot: 2026-07-28_

A retrieval-augmented (RAG) chatbot for Andhra Pradesh government officials, answering
questions on GDP/GSDP/GVA estimation methodology, district economic profiles, and
constituency/mandal vision plans — grounded in official material, with citations.

---

## Current state

- **Chatbot**: Streamlit app (`app.py`), semantic RAG over ~59,388 chunks (Cohere
  `embed-english-v3.0`, 1024-dim). LLM providers: Groq (`llama-3.3-70b`, default for
  deploy), Gemini, and a local **Claude Code (`claude -p`) backend** used as a backup.
- **Landing site**: `landing/index.html` — single-page site with an interactive AP
  district map, stats, and links into the chatbot.
- **Theme**: both the site and the chatbot are now in a shared **light theme**
  (off-white `#F4F7F4`, neon-green fills `#01EF6C`, readable green text `#0A8F45`,
  JetBrains Mono + Inter).

## What was built and evaluated (this cycle)

- **Gold benchmark** (`gen_gold.py` -> `gold_prompts.jsonl`): 450 prompts, 390 numeric
  (objective ground truth) + 60 conceptual.
- **Benchmark runner** (`run_bench.py`, `st_stub.py`): runs the live pipeline, grades
  two layers, logs per-prompt, reports Wilson 95% intervals.
- **Stress harness** (`build_stress.py` + workflow): 25 adversarial prompts.
- **Optimisation loop** (`optimize_reasoning.py`) + few-shot / certification experiments.
- Judge = Claude (Sonnet/Opus) via Claude Code; answerer benchmarked on Haiku.

## Headline results (cheapest model, Claude Haiku)

| Layer | Result | 95% CI |
| --- | --- | --- |
| Retrieval accuracy | 100% (195/195) | [98.1, 100] |
| Numeric factual | 98.8% (79/80) | [93.3, 99.8] |
| Conceptual reasoning (clean context) | 90% (27/30) | [74.4, 96.5] |
| Adversarial stress | 96% (24/25) | — |
| Prompt injection resistance | 5/5 | — |
| Fabrication rate | < 1% | — |

**Key finding**: context quality is the main lever, not prompt engineering or a bigger
model. Three prompt edits (auto-optimiser, few-shot, superlative-hedge) each regressed
accuracy on certification and were rejected. The base prompt is a local optimum.

## Known gaps (designed, not yet run)

- **Control charts for drift** — needs a live daily error-rate time series (no production
  traffic yet). A 1-week pilot plan is drafted.
- **Faithfulness as a formal metric** (RAGAS-style) — we judged correctness directly; the
  formal scorer is a ~1-day build, not yet done.

## Fixes landed

- Production crash fix: `embeddings.embed_query` rotates across all Cohere keys on 429
  (a single quota-exhausted key no longer takes the app down); retrieval failure now
  shows a friendly message instead of crashing (commit `8869eb2`).
- Per-capita / population unit fix (Rs. per person, thousands — not Cr.).
- Retrieval fix for table/topical queries (mandal paddy productivity, etc.).

## Running locally (backup demo)

- Chatbot: `streamlit run app.py` (or the `swarna-chatbot` launch) on port 8501,
  with `LLM_PROVIDER=claude` in `.env` to answer via the local Claude CLI.
- Landing: static server on port 8080 (`swarna-landing` launch). Its "open assistant"
  links auto-detect localhost and point at the local chatbot.
